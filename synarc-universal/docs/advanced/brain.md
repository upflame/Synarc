# The Brain

> The brain is a **lightweight, human-readable** state store. It is not the source of truth (that is `git`). It is regenerated by agents on session start and is meant to be skimmed, not edited.

---

## Why a brain?

LLM-based agents forget everything between sessions. To resume work, they need:

- The current state of the codebase
- The architecture (modules, dependencies)
- Open incidents and decisions
- The last ledger entry and aggregate risk

The brain is a tiny directory of Markdown files that answer these questions in seconds. It is **deliberately lossy** — it summarizes `git`, it does not replace it.

---

## Directory layout

```text
brain/
├── CURRENT_STATE.md     # What is in progress right now
├── MODULE_MAP.md        # Modules, dependencies, entry points
├── API_CONTRACTS.md     # Public API surface
├── DECISIONS.md         # ADRs (Architecture Decision Records)
├── INCIDENTS.md         # Open + recent incidents
├── RUNS.md              # Last N session summaries
├── GLOSSARY.md          # Domain terms
└── LEDGER.md            # Append-only change log
```

For agents with persistent mode (Claude Code, OpenCode, Cline), the brain lives in the project root. For agents without persistent mode (Cursor, Windsurf, Copilot, Gemini), the brain is regenerated per session in memory.

## What is in each file

### `CURRENT_STATE.md`

The most-recent state. Updated on every change. Includes:

- Active branch and last commit
- Aggregate risk from the last ledger entry
- Open incidents, open PRs
- In-progress tasks (intent contracts in flight)

### `MODULE_MAP.md`

Module-level architecture. For each module: purpose, dependencies, entry points, key files, test coverage. Generated by analyzing the dependency graph and package manifests.

### `API_CONTRACTS.md`

Every public API surface — HTTP endpoints, library exports, CLI commands. Includes request/response shapes, error codes, and rate limits. Updated when API contracts change.

### `DECISIONS.md`

Append-only ADR list. Each decision has: title, context, decision, consequences, date, author.

### `INCIDENTS.md`

Open incidents (active) and the last 20 resolved. Each incident has: severity, status, IC, root cause, resolution.

### `RUNS.md`

Last 10 session summaries. Each run has: timestamp, agent_id, contract_id, work_type, verdict, time spent.

### `GLOSSARY.md`

Domain terms specific to the project. Acronyms, business terms, naming conventions.

### `LEDGER.md`

Append-only change log. One entry per mutation. See [`ledger-entry.schema.json`](../../shared/schemas/ledger-entry.schema.json).

## When the brain is regenerated

| Event | What regenerates |
|---|---|
| Session start (cold) | `CURRENT_STATE.md`, `MODULE_MAP.md`, `RUNS.md` |
| File mutation | `CURRENT_STATE.md`, `LEDGER.md` (append) |
| API contract change | `API_CONTRACTS.md` |
| New decision | `DECISIONS.md` (append) |
| Incident open/close | `INCIDENTS.md` |
| Session end | `RUNS.md` (append summary) |

Regeneration is incremental — only the affected file is rewritten, not the whole brain.

---

## What the brain is NOT

- ❌ **Not a database.** Do not put structured query patterns on it.
- ❌ **Not the source of truth.** The source of truth is `git`. The brain is a summary.
- ❌ **Not editable in real-time by humans.** It is regenerated by agents. If you find an error, fix the source (the code, the doc, the commit) and the brain will be updated next time.
- ❌ **Not shared between projects.** Each project has its own `brain/`. Cross-project state goes in the `audit trail`, not the brain.

## Brain schema

Every file in the brain has a YAML frontmatter that matches [`brain-document.schema.json`](../../shared/schemas/brain-document.schema.json):

```yaml
---
document_type: current_state
version: 7
last_updated: 2026-06-22T10:00:00Z
related_documents:
  - MODULE_MAP.md
  - LEDGER.md
---
```

`document_type` is the kind of file. `version` is monotonically increasing per document type. `last_updated` is set by the regenerating agent.
